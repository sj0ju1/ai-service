# Tools README

## Web Search 설계 및 확증편향 완화 전략
Web Search는 **최신 반도체 공개 신호 수집용**으로 사용합니다. 기업 보도자료만 읽으면 확증편향이 발생할 수 있으므로, **긍정/부정/객관 지표 기반의 다중 쿼리 전략**을 적용했습니다.

적용 내용:
- 공식 발표/제품 페이지 우선 탐색
- `yield`, `thermal`, `power`, `limitation`, `issue`, `drawback` 같은 부정 신호 동시 탐색
- `patent`, `hiring`, `conference`, `news` 같은 객관 지표 기반 쿼리 추가
- 기업 발표, 언론 기사, 특허, 채용 공고 등 다양한 출처 활용
- 결과가 한쪽으로 치우치거나 출처가 약하면 `Supervisor`가 **재검색**을 지시

## RAG / Retrieve 설계
RAG는 **JEDEC 표준 문서, 해외 논문, 기업 기술 자료 PDF**를 대상으로 구성했습니다.  
웹 검색이 최신성을 담당한다면, RAG는 **기술 규격·논문·정적 근거를 안정적으로 공급하는 층**입니다.

강점:
- JEDEC 표준 문서를 통해 기업 발표의 주장과 실제 규격 정합성을 교차 검증
- 논문과 기술 자료를 통해 제품 소개 수준을 넘어 기술 맥락까지 보강
- chunk 기반 검색 후 문서 수준으로 근거를 정리

## 오픈소스 임베딩 모델 선정

| 후보 모델 | 특징 | 판단 |
|---|---|---|
| `jhgan/ko-sroberta-multitask` | 한국어 문장 임베딩에 특화된 경량 모델 | 국문 질의에는 유리하지만 영문 기술 PDF 대응력이 제한적 |
| `intfloat/multilingual-e5-large` | 다국어 지원이 뛰어난 고성능 임베딩 모델 | 후보로 적합하지만 긴 기술 문서 처리와 실전 밸런스 비교 필요 |
| `BAAI/bge-m3` | 다국어, 다중 입도, 다중 기능을 지원하는 최신 SOTA 모델 | **최종 선정** |

최종 선정 모델은 **`BAAI/bge-m3`** 입니다.

선정 근거:
- 수집된 PDF 데이터(JEDEC 표준 규격서, 해외 논문 등)는 **영문 중심**
- 사용자 질의와 기업 분석 맥락은 **국문 중심**
- 따라서 **다국어/교차언어 검색**이 매우 중요
- `bge-m3`는 교차 언어 검색 성능이 우수
- 반도체 논문은 긴 문맥 이해가 중요하므로 **최대 8192 토큰 입력 지원**과 Dense 의미 벡터 성능을 높게 평가

## Retrieval 기법 선정

| 후보 기법 | 특징 | 판단 |
|---|---|---|
| Sparse Retrieval (`BM25`) | 단어 빈도 기반 검색으로 고유명사 매칭에 강하지만 문맥 이해에 약함 | 버전/제품명 매칭에 유리 |
| Dense Retrieval (`FAISS`) | 임베딩 벡터 기반 의미 검색으로 문맥 이해는 좋지만 제품명/버전 등 정밀 키워드 매칭이 약할 수 있음 | 의미 검색에 유리 |
| Hybrid Retrieval (`Ensemble`) | Sparse와 Dense의 장점을 결합 | **최종 선정** |

최종 선정 기법은 **`Hybrid Retrieval (BM25 + FAISS Ensemble)`** 입니다.

선정 근거:
- 반도체 분야는 `HBM4`, `CXL 1.1`, `JEDEC` 같은 **고유 명사와 버전 정보**가 중요
- Dense 검색만으로는 숫자/버전이 미세하게 다른 문서를 놓치는 문제가 있었음
- BM25와 FAISS(BGE-M3)를 **4:6 가중치**로 결합한 `EnsembleRetriever` 사용
- 의미적 유사성과 정확 키워드 매칭을 동시에 확보
